Makros & Präprozessor

Makros

Makros in C++ sind Code-Fragmente, die eine Bezeichnung erhalten. Bevor der eigentliche Compiler den Code übersetzt, ersetzt der Präprozessor diese Bezeichnungen im gesamten Quelltext durch den definierten Code.

Makro-ähnliche Objekte:

#define PI 3.14159
#define BUFFER_SIZE 1024

Funktionstyp-Makros (Function-like Macros):

  • Diese Makros verhalten sich optisch wie Funktionen und können Argumente entgegennehmen.
  • Ein Aufruf wie SQUARE(5) wird im Code durch ((5) * (5)) ersetzt. Hinweis: Die vielen Klammern sind wichtig, um Fehler bei der operator-Reihenfolge zu vermeiden
#define SQUARE(x) ((x) * (x))

In älterem C-Code waren Makros allgegenwärtig. Im modernen C++ (ab C++11) gelten sie jedoch oft als schlechter Stil und sollten durch sicherere Alternativen ersetzt werden.

header-Dateien

Zu den Präprozessor-Statements zählen auch #include statements. Sie geben an, welche Bibliotheken und Dateien eingebunden werden sollen.

  • will man eine Bibliothek einbinden, nutzt man: #include <BibliothekenName>
  • will man eine header-Datei einbinden, nutzt man: #include "HeaderDatei.h" oder headerDatei.hpp"
  • die " geben dem Präprozessor die Information im Projektverzeichnis zu suchen, also im gleichen Ordner, in dem sich die .cpp-Datei befindet

Wenn Sie eine Headerdatei (z. B. Auto.h) in mehreren anderen Dateien Ihres Projekts einbinden, kopiert der Präprozessor den Inhalt von Auto.h jedes Mal eins zu eins in diese Dateien.

Wenn in Auto.h eine Klasse definiert ist, sieht der Compiler dieselbe Klasse plötzlich mehrfach. Das führt zu einem Kompilierfehler ("Redefinition of class..."). Um das zu verhindern, nutzt man entweder Include Guards oder #pragma once.

Include Guards

  • Diese Methode ist der traditionelle, ISO-C++-standardisierte Weg, um sicherzustellen, dass der Inhalt einer Headerdatei nur genau einmal vom Compiler gelesen wird.
#ifndef AUTO_H
#define AUTO_H

class Auto
{
    //Klasseninhalt
};
#endif
  • #ifndef AUTO_H bedeutet: "Wenn das Makro AUTO_H noch nicht definiert ist (if not defined)..."
  • Der Präprozessor springt in die nächste Zeile und definiert mit #define AUTO_H genau dieses Makro.
  • Danach folgt der eigentliche Code der Headerdatei.
  • #endif schließt den Block ab.
  • Wird diese Headerdatei im selben Kompiliervorgang ein zweites Mal aufgerufen, sieht der Präprozessor, dass AUTO_H bereits existiert. Er springt sofort zum #endif und ignoriert den Code dazwischen komplett.
  • Die moderne Alternative: #pragma once

header-Dateien und Modularisierung

In C++ werden Header-Dateien genutzt, um Code sauber in mehrere Dateien aufzuteilen und dem Compiler mitzuteilen, welche Funktionen existieren, bevor sie benutzt werden.

  • in C++ ist die Dateiendung einer header-Datei dem Compiler egal, er muss lediglich den Quellcode aus dieser Datei, in die Datei kopieren, in der die header-Datei eingebunden wird
  • Die Konvention ist allerdings die Dateiendung .h für header-Dateien, die in der Sprache C und C++ funktionieren, diese ernthalten C-Code.
  • .hpp hingegen kennzeichnen header-Dateien exklusiv für C++

Ein Programm soll übersichtlicher werden und wird deshalb in mehere Dateien aufgeteilt:

  • in mathematik.hpp wird eine Funktion namens addieren() deklariert, es wird nicht definiert, was sie tut.
  • überall wo mathematik.hpp eingebunden wird, wird damit dem Compiler bekannt gegeben, das eine Funktion namens addieren() existiert.
  • das ermöglicht es, die Funktion überall in dort aufzurufen, wo die header-Datei eingebunden wird
#ifndef MATHEMATIK_HPP
#define MATHEMATIK_HPP

int addieren(int a, int b);
#endif
  • jetzt soll die Funktion auch etwas tun, hierzu muss sie definiert werden
  • die Funktion kann in einer .cpp-Datei definiert werden, die zum Beispiel mathematik.cpp heißt
  • hier bekommt die Funktion ihre eigentliche Logik, die dann über alle Dateien, die die header-Datei einbinden, gleich ist
#include "mathematik.hpp"

int addieren(int a, int b)
{
    return a + b;
}
  • nun soll addieren() in main.cpp aufgerufen und verwendet werden
  • dazu muss nur die header-Datei eingebunden werden, addieren() kann dann wie eine ganz normale Funktion genutzt werden
#include <iostream>
#include "mathematik.hpp"

int main()
{
    std::cout << addieren(5, 5);
    return 0;
}

namespaces

Namespaces (Namensräume) in C++ dienen dazu, Code logisch zu strukturieren und Namenskonflikte zu vermeiden. Wenn Sie in einem großen Projekt oder bei der Verwendung verschiedener Bibliotheken denselben Namen für eine Funktion, Klasse oder Variable verwenden, sorgt ein Namespace dafür, dass der Compiler genau weiß, welches Element gemeint ist.

  • wei Entwickler können unabhängig voneinander eine Funktion namens print() schreiben. Liegen diese in unterschiedlichen Namespaces, kollidieren sie nicht.
  • Standardbibliothek: Die gesamte C++-Standardbibliothek liegt im Namespace std (z. B. std::cout, std::vector)

Durch die Verwendung eines namespaces, kann das Programm "hello world" anders dargestellt werden, da dem Compiler nicht mitgeteilt werden muss, dass cout aus dem Standard-Namespace ist.

#include <iostream>

using namespace std; //mit using namespace std, verwendet der gesamte Code ab dem using namespace diesen namespace

int main()
{
    cout << "hello world";
    return 0;
}

Es ist jedoch besser, statt using namespace, den namespace mit :: festzulegen, wie es bisher passiert ist, so ist für jede Funktion der namespace klar und eindeutig definiert und es kann nicht zu Überschneidungen kommen.
