Makros & Präprozessor

Makros

Makros in C++ sind Code-Fragmente, die eine Bezeichnung erhalten. Bevor der eigentliche Compiler den Code übersetzt, ersetzt der Präprozessor diese Bezeichnungen im gesamten Quelltext durch den definierten Code.

Makro-ähnliche Objekte:

#define PI 3.14159
#define BUFFER_SIZE 1024

Funktionstyp-Makros (Function-like Macros):

  • Diese Makros verhalten sich optisch wie Funktionen und können Argumente entgegennehmen.
  • Ein Aufruf wie SQUARE(5) wird im Code durch ((5) * (5)) ersetzt. Hinweis: Die vielen Klammern sind wichtig, um Fehler bei der operator-Reihenfolge zu vermeiden
#define SQUARE(x) ((x) * (x))

In älterem C-Code waren Makros allgegenwärtig. Im modernen C++ (ab C++11) gelten sie jedoch oft als schlechter Stil und sollten durch sicherere Alternativen ersetzt werden.

header-Dateien

Zu den Präprozessor-Statements zählen auch #include statements. Sie geben an, welche Bibliotheken und Dateien eingebunden werden sollen.

  • will man eine Bibliothek einbinden, nutzt man: #include <BibliothekenName>
  • will man eine header-Datei einbinden, nutzt man: #include "HeaderDatei.h" oder headerDatei.hpp"
  • die " geben dem Präprozessor die Information im Projektverzeichnis zu suchen, also im gleichen Ordner, in dem sich die .cpp-Datei befindet

Wenn Sie eine Headerdatei (z. B. Auto.h) in mehreren anderen Dateien Ihres Projekts einbinden, kopiert der Präprozessor den Inhalt von Auto.h jedes Mal eins zu eins in diese Dateien.

Wenn in Auto.h eine Klasse definiert ist, sieht der Compiler dieselbe Klasse plötzlich mehrfach. Das führt zu einem Kompilierfehler ("Redefinition of class..."). Um das zu verhindern, nutzt man entweder Include Guards oder #pragma once.

Include Guards

  • Diese Methode ist der traditionelle, ISO-C++-standardisierte Weg, um sicherzustellen, dass der Inhalt einer Headerdatei nur genau einmal vom Compiler gelesen wird.
#ifndef AUTO_H
#define AUTO_H

class Auto
{
    //Klasseninhalt
};
#endif
  • #ifndef AUTO_H bedeutet: "Wenn das Makro AUTO_H noch nicht definiert ist (if not defined)..."
  • Der Präprozessor springt in die nächste Zeile und definiert mit #define AUTO_H genau dieses Makro.
  • Danach folgt der eigentliche Code der Headerdatei.
  • #endif schließt den Block ab.
  • Wird diese Headerdatei im selben Kompiliervorgang ein zweites Mal aufgerufen, sieht der Präprozessor, dass AUTO_H bereits existiert. Er springt sofort zum #endif und ignoriert den Code dazwischen komplett.
  • Die moderne Alternative: #pragma once

header-Dateien und Modularisierung

In C++ werden Header-Dateien genutzt, um Code sauber in mehrere Dateien aufzuteilen und dem Compiler mitzuteilen, welche Funktionen existieren, bevor sie benutzt werden.

  • in C++ ist die Dateiendung einer header-Datei dem Compiler egal, er muss lediglich den Quellcode aus dieser Datei, in die Datei kopieren, in der die header-Datei eingebunden wird
  • Die Konvention ist allerdings die Dateiendung .h für header-Dateien, die in der Sprache C und C++ funktionieren, diese ernthalten C-Code.
  • .hpp hingegen kennzeichnen header-Dateien exklusiv für C++

Ein Programm soll übersichtlicher werden und wird deshalb in mehere Dateien aufgeteilt:

  • in mathematik.hpp wird eine Funktion namens addieren() deklariert, es wird nicht definiert, was sie tut.
  • überall wo mathematik.hpp eingebunden wird, wird damit dem Compiler bekannt gegeben, das eine Funktion namens addieren() existiert.
  • das ermöglicht es, die Funktion überall in dort aufzurufen, wo die header-Datei eingebunden wird
#ifndef MATHEMATIK_HPP
#define MATHEMATIK_HPP

int addieren(int a, int b);
#endif
  • jetzt soll die Funktion auch etwas tun, hierzu muss sie definiert werden
  • die Funktion kann in einer .cpp-Datei definiert werden, die zum Beispiel mathematik.cpp heißt
  • hier bekommt die Funktion ihre eigentliche Logik, die dann über alle Dateien, die die header-Datei einbinden, gleich ist
#include "mathematik.hpp"

int addieren(int a, int b)
{
    return a + b;
}
  • nun soll addieren() in main.cpp aufgerufen und verwendet werden
  • dazu muss nur die header-Datei eingebunden werden, addieren() kann dann wie eine ganz normale Funktion genutzt werden
#include <iostream>
#include "mathematik.hpp"

int main()
{
    std::cout << addieren(5, 5);
    return 0;
}

namespaces

Namespaces (Namensräume) in C++ dienen dazu, Code logisch zu strukturieren und Namenskonflikte zu vermeiden. Wenn Sie in einem großen Projekt oder bei der Verwendung verschiedener Bibliotheken denselben Namen für eine Funktion, Klasse oder Variable verwenden, sorgt ein Namespace dafür, dass der Compiler genau weiß, welches Element gemeint ist.

  • wei Entwickler können unabhängig voneinander eine Funktion namens print() schreiben. Liegen diese in unterschiedlichen Namespaces, kollidieren sie nicht.
  • Standardbibliothek: Die gesamte C++-Standardbibliothek liegt im Namespace std (z. B. std::cout, std::vector)

Durch die Verwendung eines namespaces, kann das Programm "hello world" anders dargestellt werden, da dem Compiler nicht mitgeteilt werden muss, dass cout aus dem Standard-Namespace ist.

#include <iostream>

using namespace std; //mit using namespace std, verwendet der gesamte Code ab dem using namespace diesen namespace

int main()
{
    cout << "hello world";
    return 0;
}

Es ist jedoch besser, statt using namespace, den namespace mit :: festzulegen, wie es bisher passiert ist, so ist für jede Funktion der namespace klar und eindeutig definiert und es kann nicht zu Überschneidungen kommen.

Objektorientierung

Die Objektorientierte Programmierung (OOP) ist ein beliebtes Modell in der Softwareentwicklung, bei dem der Programmcode um reale oder logische "Dinge" herum aufgebaut wird. Anstatt ein Programm als eine lange Liste von Befehlen zu schreiben, teilt man es in kleinere, eigenständige Bausteine auf.

  • Wiederverwendbarkeit: Code kann an verschiedenen Stellen im Programm leicht wieder genutzt werden.
  • Code wird leichter zu warten und ist auch leichter zu erweitern
  • der Code wird verständlicher, da Programme reale Objekte abbilden

Structs

Ein struct (Struktur) in C++ ist ein selbst definierter, zusammengesetzter Datentyp. Er erlaubt es, mehrere Variablen, auch unterschiedlicher Datentypen, unter einem gemeninsamen Namen zu gruppieren. In C++ sind struct und class technisch fast identisch, der einzige Unterschid liegt in der Standard-Sichtbarkeit (Zugriffsrechte)

  • Ein struct fasst zusammengehörende Daten an einem Ort zusammen.

In einem Programm soll ein Auto beschrieben werden, das drei Eigenschaften hat, einen String, der die Marke des Autos speichert, einen int, der das Baujahr speichert und einen int, der die PS des Autos speichert. Für ein Auto sieht das dann so aus:

#include <iostream>
#include <string>

int main()
{
    std::string marke = "BMW";
    int baujahr = 2020;
    int ps = 190;
    return 0;
}

das ist bei einem einzigen Auto kein Problem, will man aber mehrere Autos erfassen, trifft man schnell auf das Problem, dass man unfassbar viele Variablen hat, die im Code verstreut sind.

  • Hierzu kann man einen struct verwenden
  • Ein struct erlaubt es, einen eigenen Datentyp zu erfinden, in dem mehrere Variablen unterschiedlicher Datentypen zusammengefasst werden.
  • zum Beispiel der Datentyp int, sagt dem Computer nur: es werden 4 Byte RAM reserviert um eine Ganzzahl darin zu speichern.
  • bei einem struct, der ein Auto speichern soll, werden also zwei Integer und ein String an Speicher reserviert
  • ein stuct ist wie ein Bauplan für ein Auto-Objekt
#include <iostream>
#include <string>

//struct global als Bauplan für ein Auto-Objekt erstellen (eigener Datentyp Auto)
struct Auto
{
    std::string marke = "BMW";
    int baujahr = 2020;
    int ps = 190;
}; //Semikolon

In C++ kann der Zugriff auf den struct mit Sichtbarkeiten (Zugriffsrechten) geregelt werden:

  • public: - alles, was hinter public folgt, kann überall im Programm gelesen und verändert werden
  • wird bei einem struct kein Zugriffsmodifizierer hingeschrieben, so ist alles im struct als public gekennzeichnet
  • private: - alles hinter private ist geschützt, von außen kann niemand darauf zugreifen
  • private wird dann benutzt, wenn der Zugriff auf Daten von außen gezielt verhindert werden soll
  • auf private Daten kann nur der struct selbst zugreifen
#include <iostream>
#include <string>

//struct global als Bauplan für ein Auto-Objekt erstellen (eigener Datentyp Auto)
struct Auto
{
    private:
        std::string marke = "BMW";
    public:
        std::string name = marke + " i4";
        int baujahr = 2020;
        int ps = 530;
}; //Semikolon!

In diesem Programm kann der Name des Autos verändert werden, die Marke allerdings nicht.

Klassen

In C++ bildet eine Klasse (Keyword class) die fundamentale Bauanleitung für benutzerdefinierte Datentypen. Auf abstrakter Ebene kapselt sie Daten (Attribute) und das Zugriffsrecht auf diese Daten in einer logischen Einheit.

  • Eine Klasse ist im Grunde ein Bauplan für einen eigenen Datentyp.
  • Eine Klasse fasst mehrere Variablen unterschiedlicher Datentypen zusammen und definiert, wer von außen auf diese Daten zugreifen kann
  • In C++ sind structs und Klassen nahezu identisch, der einzige Unterschied liegt in der Standard-Sichtbarkeit Eine Klasse ist standardmäßig private.

der folgende Code in C++ erstellt eine Klasse Auto, die die drei Merkmale: baujahr(private), und ps(public) besitzt:

#include <iostream>
#include <string>

//Klasse global als Bauplan für ein Auto-Objekt erstellen
class Auto
{
    private:
        int baujahr = 2020;
    public:
        std::string marke = "BMW";
        int ps = 530;
}; //Semikolon!

Warum werden class und struct unterschiedlich verwendet?

Obwohl beide Keywords nahezu das gleiche in C++ tun, werden sie aus sematischen Gründen und Konvention unterscheiden:

  • In der objektorientierten Programmierung sollen Objektzustände nicht ungeprüft von außen verändert werden können (safety by default) - da Klassen-Member standardmäßig auf private gesetzt werden
  • Klassen signalisieren anderen Entwicklern, dass sie nicht direkt auf Speicherzustände zugreifen sollen
  • structs werden für PODs (Plain Old Data) oder DTOs (Data Transfer Object) genutzt, also reine Datensammlungen ohne Zugriffsregeln.

Methoden

In C++ sind Methoden (oder auch Member Functions oder Elementfunktionen genannt) Funktionen, die fest in eine Klasse integriert sind. Während die Attribute (Variablen) den Zustand eines Objekts speichern, definieren die Methoden das Verhalten des Objekts und die Art und Weise, wie es mit seinen eigenen Daten arbeitet.

  • Methoden bilden die selbstdefinierte Schnittstelle zwischen den verborgenen Daten eines Objekts und der restlichen Anwendung
  • Anstatt dass externe Programmteile Rohdaten auslesen, berechnen und wieder zurückschreiben, wird diese Logik in die Methoden der Klasse verlagert
  • Methoden stellen sicher, dass alle Änderungen an den internen Variablen streng kontrolliert und nach selbst festgelegten Regeln ablaufen
  • Nicht für jedes Objekt im Arbeitsspeicher besitzt eine eigene Methode, alle Instanzen teilen sich eine Methode gemeinsam, sie existiert nur ein einziges mal im Arbeitsspeicher für die gesamte Klasse

Damit die Methode bei der Ausführung weiß, mit den Daten welcher konkreten Instanz sie arbeiten soll, nutzt C++ einen versteckten Mechanismus: Den this-Pointer. Wird eine Methode für ein bestimmtes Objekt ausgeführt, übergibt der Compiler im Hintergrund automatisch einen Zeiger auf die Speicheradresse genau dieses Objekts an die Methode. Jeder Zugriff auf eine Klassenvariable innerhalb der Methode wird über diesen this-Zeiger aufgelöst. So liest oder überschreibt die Logik zielsicher exakt die Speicherbereiche der richtigen Instanz.

Hier ist eine Klasse Auto, mit der Eigenschaft geschwindigkeit, und einer Methode beschleunigeUmEins

#include <iostream>

//Klasse Auto als Bauplan für ein Auto-Objekt
class Auto
{
    private:
        float geschwindigkeit = 0.0f;
    public:
        //beschleunigeUmEins erhöht die geschwindigkeit beim Aufruf um 1 und verändert die Daten dieses Auto-Objekts, das die Methode aufgerufen hat
        void beschleunigeUmEins()
        {
            geschwindigkeit++;
        }
}; //Semikolon!

Getter- und Setter-Methoden

Da die Variablen einer Klasse in C++ meist vor dem direkten Zugriff von außen geschützt sind (private), werden spezielle Methoden benötigt, um diese Daten sicher zu lesen oder zu schreiben.

  • Getter(Lesezugriff) - Eine Methode, die den Wert einer privaten Variable zurückgibt. Die Getter-Methode macht Daten nach außen sichtbar und schützt sie aber vor Veränderung
  • Setter(Schreibzugriff) - Eine Methode, die einen neuen Wert entgegennimmt und in die private Variable schreibt. Diese kann die Werte vor dem speichern validieren.

Dieses Programm besitzt eine Klasse Math, mit 2 privaten variablen und einer Getter- und einer Setter-Methode

#include <iostream>

class Math
{
        //private Member-Variablen, das private: kann weggelassen werden, da die Standard-Sichtbarkeit einer Klasse private ist
        int divisor = 1;
        float PI = 3.1415f;
    public:
        //Getter
        float getPI()
        {
            return PI;
        }

        //Setter
        void setDivisor(int div)
        {
            if(div != 0)
            {
                divisor = div;
            }
            else
            {
                std::cout << "Teilung durch 0 nicht möglich" << std::endl;
            }
        }
}; //Semikolon!

this

In C++ regeln das this-Keyword sowie der Arrow-Operator (->) den direkten Zugriff auf ein Objekt und dessen Member (Variablen und Methoden)

  • Da this ein Pointer auf die eigene Instanz ist, muss innerhalb der Klasse immer der Arrow-Operator (->) genutzt werden, um über this auf die eigenen Member zuzugreifen.

Hier eine Beispielklasse, die den Bauplan für ein Spieler-Objekt darstellt:

#include <iostream>

class Spieler
{
        int posX = 0;
    public:
        //Getter
        int getPosX()
        {
            return posX;
        }

        //Setter
        void setPosX(int posX)
        {
            this->posX = posX; //this->posX ist die position x des Objektes, posX ist der parameter der Methode, dessen Wert gespeichert werden soll
        }
}; //Semikolon!

Setter dienen nicht nur der simplen Werteprüfung, sondern vor allem dem Erhalt von Invarianten. Eine Invariante ist ein Zustand, der logisch immer gültig sein muss. Oft gehören mehrere Variablen untrennbar zusammen und dürfen nur gemeinsam geändert werden. Das Videospiel-Szenario:

  • Eine Spielerfigur hat eine Position im 2D-Raum, die in den Variablen x und y gespeichert ist. Wenn man diese von außen nacheinander über zwei separate Setter (setX und setY) ändert, entsteht ein gefährliches Problem
  • Der Spieler steht auf der Position (10, 10).
  • Er soll durch ein Event auf (20, 20) teleportiert werden.
  • Das Programm führt Befehle nacheinander aus.
  • Das Programm führt setX(20) aus.
  • In diesem exakten Moment befindet sich der Spieler auf (20, 10).
  • Danach führt das Programm setY(20) aus.
  • Dieser fehlerhafte Zwischenzustand bei existiert vielleicht nur für Mikrosekunden, kann aber fatale Bugs auslösen. Wenn genau in diesem Moment ein anderer Thread die Position ausliest oder die Physik-Engine eine Kollisionsabfrage durchführt, könnte der Spieler bei (20, 10) durch eine eigentlich massive Wand fallen oder Schaden nehmen.

Die Lösung: Ein gemeinsamer Setter

class Spieler
{
        int x = 0;
        int y = 0;
    public:
        //gemeinsamer Setter
        void setPosition(int x, int y)
        {
            this->x = x;
            this->y = y;
        }
        //andere variante für die Setter-Methode:
        /*
        void setPosition(int neuesX, int neuesY)
        {
            x = neuesX;
            y = neuesY;
        }
        */
}; //Semikolon!

mit dem gemeinsamen Setter kann sichergestellt werden, dass x und y immer zusammen Werte zugewiesen bekommen

Konstruktor / Destruktor

Der Konstruktor und der Destruktor sind besondere Methoden einer Klasse. Sie besitzen keinen Rückgabetyp (nicht einmal void) und tragen exakt denselben Namen wie die Klasse selbst. Der Konstruktor wird automatisch beim Erstellen des Objektes aufgerufen, der Destruktor, wenn das Objekt zerstört wird. Um den Destruktor optisch zu unterscheiden, wird seinem Namen eine Tilde (~) vorangestellt.

Konstruktor

Wenn ein Objekt im Arbeitsspeicher angelegt wird, enthält dieser Speicherplatz oft noch zufälligen "Datenmüll" von vorherigen Programmen. Der Konstruktor sorgt dafür, dass das Objekt direkt ab der ersten Millisekunde seiner Existenz in einem sauberen, definierten Zustand (einer gültigen Invariante) ist. Man unterscheidet grob zwei Arten:

  • Standardkonstruktor (Default Constructor): Nimmt keine Parameter entgegen und setzt Standardwerte
  • Parametrisierter Konstruktor: Nimmt Werte von außen entgegen (z. B. Startkoordinaten), um das Objekt spezifisch einzurichten

Destruktor

Der Destruktor (~Klassenname()) wird exakt dann aufgerufen, wenn die Lebensdauer eines Objekts endet. Das passiert entweder automatisch, wenn eine lokale Variable ihren Gültigkeitsbereich (die umschließenden geschweiften Klammern } ) verlässt, oder manuell, wenn ein dynamisch erzeugtes Objekt mit delete gelöscht wird.

class DatenPuffer
{
        int* speicher;
        int groesse;
    public:
        //Parametrisierter Konstruktor
        DatenPuffer(int anzahlElemente)
        {
            groesse = anzahlElemente;
            //Fordert dynamisch Speicher auf dem Heap an
            speicher = new int[groesse];
        }

        ~DatenPuffer()
        {
            //Gibt den angeforderten Speicher zwingend wieder frei
            delete[] speicher; 
        }
}; //Semikolon!

Ein Anwendungsfall für einen Konstruktor könnte bei der oben erstellten Klasse Spieler sein, das ein Spieler-Objekt bei der erstellung bereits Start-Werte für die Position mitgegeben bekommt.

class Spieler
{
        int x = 0;
        int y = 0;
    public:
        //gemeinsamer Setter
        void setPosition(int x, int y)
        {
            this->x = x;
            this->y = y;
        }
        //Konstruktor
        Spieler(int x, int y)
        {
            this->x = x;
            this->y = y;
        }
}; //Semikolon!

Objekt / Instanz

Ein Objekt ist die Umsetzung der Klasse. Wenn die Klasse der Bauplan für ein Haus ist (sie legt fest, wo Wände und Türen sind), dann ist das Objekt das fertige, gebaute Haus, in das man einziehen kann. Der Begriff Instanz wird meist synonym zu Objekt verwendet. Man sagt: "eine Klasse wird instanziieret", was bedeutet: Aus der Klasse wird ein Objekt im Arbeitsspeicher, das mit echten Daten gefüllt wird. Aus einer einzigen Klasse (z. B. Spieler) können hunderte unabhängige Objekte (Instanzen) erzeugt werden, von denen jedes seine eigenen Werte hat.

Objekte erzeugen

In C++ hat man die Wahl zwischen zwei grundlegend verschiedenen Speicherarten: dem Stack (ohne new) und dem Heap (mit new)

Objekte auf dem Stack erzeugen

  • Dies ist der Standardweg in C++ und sollte immer bevorzugt werden, wenn möglich. Das Objekt wird als normale lokale Variable erstellt.
  • Lebensdauer des Objekts: Sobald der aktuelle Block (z. B. eine Funktion oder Schleife) beendet wird, wird automatisch der Destruktor aufgerufen und der Speicher wieder freigegeben.
//Erstellung eines Spieler-Objekts, wie eine Variable, vom Typ Spieler mit dem Namen meinSpieler
Spieler meinSpieler; 
//Mit Parametern für den Konstruktor, erzeugt ein Spieler-Objekt namens gegner
Spieler gegner(10, 20);

Objekte auf dem Heap erzeugen

  • Das Keyword new wird in C++ nur verwendet, wenn das Objekt den aktuellen Code-Block(Scope) überleben soll oder extrem groß ist
  • Das Objekt wird auf dem "Heap" (dynamischer Speicher) erstellt. new gibt nicht das Objekt selbst zurück, sondern nur einen Zeiger (Pointer) auf die Speicheradresse des Objekts
  • das objekt existiert so lange, bis es explizit mit delete zerstört wird
Spieler* dynamischerSpieler = new Spieler();

Um direkt auf public-Werte und auf die Methoden der Objekte zugreifen zu können, kommt es darauf an, wie das objekt erzeugt wurde. Der Zugriff auf ein Objekt, das auf dem Stack erzeugt wurde:

class Spieler
{
    public:
        int lebenspunkte; //Public Variable (direkt zugreifbar)

        void heilen()
        {
            lebenspunkte = 100;
        }
}; //Semikolon!

int main()
{
    //Objekt erzeugen (Stack)
    Spieler held;

    //Direkter Zugriff auf eine public Variable mit '.'
    held.lebenspunkte = 50;

    //Aufruf einer public Methode mit '.'
    held.heilen(); 

    return 0;
}

Wenn das Objekt auf dem Heap erstellt wurde, erfolgt der Zugriff über den Preil-Operator (->)

class Spieler
{
    public:
        int lebenspunkte; //Public Variable (direkt zugreifbar)

        void heilen()
        {
            lebenspunkte = 100;
        }
}; //Semikolon!

int main()
{
    //Objekt erzeugen (Heap)
    Spieler* heldZeiger = new Spieler();

    //Direkter Zugriff auf eine public Variable mit '->'
    heldZeiger->lebenspunkte = 50;

    //Aufruf einer public Methode mit '->'
    heldZeiger->heilen();

    //ZWINGEND ERFORDERLICH: Manuelles Loeschen!
    delete heldZeiger;

    return 0;
}

Der Zugriff auf den Konstruktor und Destruktor ist nicht möglich, da diese bei der Erzeugung bzw. der Zerstörung der Objekte automatisch aufgerufen werden.

Klassen auslagern

Es lohnt sich in großen Projekten mit mehreren Beteiligten, darüber Nachzudenken, Klassen und Methoden in Dateien uszulagern, um die Projektstruktur übersichtlicher zu gestalten. Zum Beispiel:

  • main.cpp: enthält die main()-Funktion und hier werden Objekte erzeugt.
  • Klasse.hpp: enthält die Klasse (je Klasse eine .hpp Datei)
  • Klasse.cpp: die Mehtoden der Klasse werden in eine separate .cpp datei ausgelagert

Hier wird das ganze an der Klasse Spieler veranschaulicht:

bisher:

#include <iostream>
class Spieler
{
    public:
        int posX;
        int posY;

        void printPos()
        {
            std::cout << PosX < < ", " << PosY;
        }
}; //Semikolon!

int main()
{
    //Objekt erzeugen (Heap)
    Spieler* spielerZeiger = new Spieler();

    spielerZeiger->PosX = 10;
    spielerZeiger->PosY = 20;

    spielerZeiger->print();

    delete spielerZeiger;

    return 0;
}

ausgelagert:

Spieler.hpp:

#ifndef SPIELER_H
#define SPIELER_H

class Spieler
{
    public:
        int posX;
        int posY;

        void printPos(); //Methode wird deklariert, es wird nicht definiert, was sie tut
}; //Semikolon!

#endif

Spieler.cpp:

#include "Spieler.hpp"
#include <iostream>

//Spieler:: bedeutet, die nachfolgende Methode gehört zu der Klasse Spieler
Spieler::void printPos()
{
    std::cout << PosX < < ", " << PosY;
}

main.cpp:

#include "Spieler.hpp"
#include <iostream>
int main()
{
    //Objekt erzeugen (Heap)
    Spieler* spielerZeiger = new Spieler();

    spielerZeiger->PosX = 10;
    spielerZeiger->PosY = 20;

    spielerZeiger->print();

    delete spielerZeiger;

UML-Klassendiagramme

UML steht für Unified Modeling Language (vereinheitlichte Modellierungssprache). Wenn Architekten ein Gebäude entwerfen, zeichnen sie vorher einen Bauplan, damit jeder genau weiß, wo die tragenden Wände hinkommen. In der Softwareentwicklung ist UML genau dieser Bauplan. UML hilft Entwicklern, sich einen schnellen Überblick zu verschaffen und die Architektur eines Programms im Team zu besprechen, ohne sich in tausenden Zeilen Code zu verlieren. Ein UML-Klassendiagramm zeigt dabei auf einen Blick, welche Bausteine (Klassen) das System hat und was die daraus erstellten Objekte können.

Darstellung einer Klasse:

eine Klasse Student, enthält einen String name, einen int matrikelnummer und einen int alter

#include <iostream>
#include <string>
class Student
{
    private:
        std::string name;
        int matrikelnummer;
        int alter;

    public:
        Student(std::string name, int matrikelnummer, int alter)
        {
            this->name = name;
            this->matrikelnummer = matrikelnummer;
            this->alter = alter;
        }
        void PrintStudentInfo()
        {
            std::cout << "Name:\t\t" << name << std::endl;
            std::cout << "Matrikelnummer:\t" << matrikelnummer << std::endl;
            std::cout << "Alter:\t\t" << alter << std::endl;
        }
}; //Semikolon!

int main()
{
    Student* s1 = new Student("Julia Mueller", 200151305, 19);

    s1->PrintStudentInfo();

    delete s1;

    return 0;
}
